# ニュース/朝礼ブリーフィング型 解説音声ワークフロー

資料・トピックを **アンカー＋レポーター** による短時間ブリーフィングに変換する。
見出しで全体像 → 各項目を手短に。忙しい聞き手が短時間で要点を掴める構成。
毎朝の定期配信に最適。

入力: **$ARGUMENTS**（資料パス or トピック、任意の workspace_root / workspace_id。無ければ聞く）。

共通メカニクスは `../_shared/` を参照:
[PIPELINE](../_shared/PIPELINE.md) /
[SCRIPT-SCHEMA](../_shared/SCRIPT-SCHEMA.md) /
[SOURCE-INGEST](../_shared/SOURCE-INGEST.md) /
[VOICE-CATALOG](../_shared/VOICE-CATALOG.md)

## このフォーマットの狙い

- **話者数**: 1〜2 名（アンカー主体。詳報にレポーターを追加）。
- **役割**: アンカー＝進行・見出し読み・つなぎ。レポーター＝個別項目の詳報。
- **トーン**: 明瞭・簡潔・きびきび。感情は控えめ、情報密度を高く。
- **長さ**: 全体 2〜5 分。1 項目 20〜40 秒。冗長さは厳禁。

## 手順

### 1. 環境チェック
[PIPELINE P0](../_shared/PIPELINE.md#p0-環境チェック最初に必ず)。

### 2. 資料を見出しへ
[SOURCE-INGEST](../_shared/SOURCE-INGEST.md) で要点カード化。ブリーフィングは
各カードの `key_point` を**1 行の見出し**に凝縮する。構成:

1. **オープニング** — 日付＋「本日の3本」など見出し予告（ヘッドライン）。
2. **項目** — 各 3〜5 文。「何が / なぜ重要 / どうする」を1文ずつ。
   詳報が要る項目だけレポーターに渡す。
3. **クロージング** — 一言まとめ or 次回予告。

**削る勇気**が要る。1 項目 40 秒を超えたら削る。データは代表値のみ
（[SOURCE-INGEST スライド/データ](../_shared/SOURCE-INGEST.md#スライド--データpptx--xlsx)）。

### 3. キャスティング（人間チェックポイント）
[PIPELINE P2](../_shared/PIPELINE.md#p2-キャスティング人間チェックポイント--必須)。
推奨: アンカー=澤原玄二郎 or 阿井田茂（きびきびした声）、
レポーター=hinakoyuhara or morioki。`casting.template.toml` を雛形に。

### 4. 発音辞書
[PIPELINE P3](../_shared/PIPELINE.md#p3-発音辞書)。人名・社名・地名を確実に。

### 5. 台本 JSONL
`script.template.jsonl` を参考に。[SCRIPT-SCHEMA](../_shared/SCRIPT-SCHEMA.md) 準拠。
**ブリーフィングの書き方のコツ:**

- 全体 `speed` 1.0〜1.05 でテンポよく。だらけさせない。
- `intensity` は 1.0 前後で淡々と。重大項目のみ 1.2 で軽くメリハリ。
- 見出しの後に `pause_after_ms` 500 で「これから詳報」の呼吸。
- 項目間は `pause_after_ms` 700＋scene 増で区切る。
- 数字・固有名詞は `speed` 0.9 で明瞭に。

### 6〜9. 合成・試聴・マスタリング・納品
[PIPELINE P5–P9](../_shared/PIPELINE.md#p5-ボイスオーディション任意)。配信は mp3。

## 定期配信（スケジュール連携）

毎朝の自動配信にするなら、生成後に定期タスクを提案・設定できる。
`schedule` スキル / `mcp__scheduled-tasks__create_scheduled_task` を使い、
例: cron `0 7 * * *`（毎朝7時）で「指定ソースを取得→本ワークフローで
ブリーフィング音声を生成」を回す。ソースが日々更新される前提なら、
台本 id は日次でリセットしてよい（別ワークスペース/日付キー運用）。
定期配信では**キャスティングを固定**し、毎回の承認を省ける運用にすると軽い。
