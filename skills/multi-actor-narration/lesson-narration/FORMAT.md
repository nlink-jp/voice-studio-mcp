# 教材ナレーション型 解説音声ワークフロー

資料・テーマを **講師＋生徒役** の Q&A 形式教材として音声化する。
講師が段階的に解説し、生徒役が学習者のつまずきを代弁して質問する。
学び直し・研修・オンボーディング教材に向く。

入力: **$ARGUMENTS**（資料パス or テーマ、任意の workspace_root / workspace_id。無ければ聞く）。

共通メカニクスは `../_shared/` を参照:
[PIPELINE](../_shared/PIPELINE.md) /
[SCRIPT-SCHEMA](../_shared/SCRIPT-SCHEMA.md) /
[SOURCE-INGEST](../_shared/SOURCE-INGEST.md) /
[VOICE-CATALOG](../_shared/VOICE-CATALOG.md)

## このフォーマットの狙い

- **話者数**: 2 名（講師＋生徒役）。理解度の違う生徒を2名にする構成も可。
- **役割**: 講師＝体系立てて解説・要点整理・つまずき解消。生徒役＝学習者の
  疑問を代弁（「そこが分からない」を言語化）・復唱・確認。
- **トーン**: 落ち着いて丁寧。急がず、噛み砕く。生徒役は素直で好奇心旺盛。
- **設計思想**: 情報を並べるのでなく**理解の段階**に沿う。既知→未知へ。
- **長さ**: 1 単元 5〜10 分。章立てで分割。

## 手順

### 1. 環境チェック
[PIPELINE P0](../_shared/PIPELINE.md#p0-環境チェック最初に必ず)。

### 2. 資料を学習ステップへ
[SOURCE-INGEST](../_shared/SOURCE-INGEST.md) で要点カード化。教材では
`listener_question` を**生徒のつまずきポイント**に変換し、学習が積み上がる
順に並べる。構成:

1. **導入** — 講師がこの単元のゴール（「終わったら〜が分かる」）を提示。
2. **本編** — 概念を小ステップに分解。各ステップで
   「講師の説明 → 生徒の質問/つまずき → 講師の噛み砕き → 生徒の復唱で定着」。
   前のステップの理解を前提に次へ積む。
3. **確認** — 講師がミニ問いかけ、生徒が答える。要点を3つに整理。
4. **まとめ** — ゴールの再確認と次の単元予告。

抽象概念には**具体例・アナロジー・図の言語化**を必ず添える。

### 3. キャスティング（人間チェックポイント）
[PIPELINE P2](../_shared/PIPELINE.md#p2-キャスティング人間チェックポイント--必須)。
推奨: 講師=ろてじん / 猩々博士 / 花音（落ち着いた声）、
生徒役=コハク or 中2 or るな（若く素直な声）。**明確な年齢・声質差**で
役割を聞き分けやすく。`casting.template.toml` を雛形に。

### 4. 発音辞書
[PIPELINE P3](../_shared/PIPELINE.md#p3-発音辞書)。教材は用語の正確な読みが命。
専門語は初出で生徒に読みと意味を確認させる台本にすると辞書と教育を兼ねられる。

### 5. 台本 JSONL
`script.template.jsonl` を参考に。[SCRIPT-SCHEMA](../_shared/SCRIPT-SCHEMA.md) 準拠。
**教材の書き方のコツ:**

- 講師はゆっくり明瞭に `speed` 0.92〜0.97。要点は 0.9 でさらにゆっくり。
- 生徒の質問前に `pause_after_ms` 500〜700 の「考える間」。
- 生徒の**復唱**（「つまり〜ということですね」）で定着させる。`intensity` 1.1。
- 生徒の「分からない」は責めでなく素直に（「ここがピンと来なくて」）。
- 新概念の導入時は scene を増やし、`pause_after_ms` 1000 で区切る。
- 箇条書きの列挙は各項目 `pause_after_ms` 300 でリズム。

### 6〜9. 合成・試聴・マスタリング・納品
[PIPELINE P5–P9](../_shared/PIPELINE.md#p5-ボイスオーディション任意)。
教材は m4b にすると単元＝章で頭出ししやすい（scene が章になる）。
