# ADR-0009: radio-drama スキルは skills-series でなく本リポジトリに同梱する

- **Status**: Accepted (2026-07-04)
- **Supersedes**: RFP の「スキルは skills-series の別プロジェクト」というスコープ判断

## Context

RFP 時点では、エージェント向けの制作手順スキル(radio-drama)は
skills-series の別プロジェクトとして開発する計画だった。しかし v0.1.0
リリースとパイロット制作を経て、次の実態が明らかになった:

- スキルの中身の大半は**本 MCP の契約への参照**である: 台本 JSONL
  スキーマ(canonical は `internal/script`)、6ツールの引数と返却、
  エラーコード分岐表、ライセンスステータスの3値。
- これらはすべて本リポジトリで進化する。別リポジトリに置くと、ツール
  追加・スキーマ変更・エラーコード変更のたびに**2リポジトリ間の同期**が
  必要になり、ドリフトの温床になる(実際、ADR-0008 の3値化だけでも
  手順書側の追従修正が発生した)。
- 手順書(docs/reference/agent-workflow)とサンプル素材(samples/)は
  すでに本リポジトリにあり、スキルはその運用形にすぎない。
- skills-series は「開発プロセス自動化のための汎用スキル」(rfp 等)の
  モノレポであり、特定プロダクトの付属スキルは性格が異なる。

## Decision

radio-drama スキルを本リポジトリの `skills/radio-drama/SKILL.md` に同梱し、
`make install-skill` で `~/.claude/skills/` に配置する。

- スキルは MCP サーバーと**同一コミット・同一バージョンで進化**する。
- `skills/skills_test.go` がスキルとサーバーの整合を機械検査する:
  全ツール名への言及、全エラーコードの分岐表掲載、スキーマ例のフィールド
  が parser の受理集合と一致すること。ツール追加やスキーマ変更でスキルの
  更新を忘れるとテストが落ちる。
- docs/reference/agent-workflow(両言語)は設計文書として残し、スキルは
  その運用形とする(スキルが正、手順書は解説)。

## Consequences

- スキーマ・ツール・エラーコードの変更が1コミット・1レビューで完結する。
- スキルの配布は「リポジトリを clone して make install-skill」となり、
  リリース zip には含まれない(スキル利用者は開発者/クリエイターであり
  リポジトリを持っている前提。必要になれば zip 同梱は後から足せる)。
- skills-series には radio-drama を追加しない。組織カタログ上の見え方は
  voice-studio-mcp の機能の一部となる。

## Alternatives considered

- **skills-series の別プロジェクト**(当初計画): 契約の同期コストと
  ドリフトリスクが利点(スキルの一元管理)を上回る。不採用。
- **スキルをリリース zip に同梱**: 現時点で必要性がない。将来の需要次第。
- **手順書(agent-workflow)を廃止しスキルに一本化**: 手順書は「なぜ」を
  含む設計文書として価値が残るため併存させ、役割を明記する。
