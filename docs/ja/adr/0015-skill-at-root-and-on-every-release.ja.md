# ADR-0015: スキルはリポジトリ直下に置き、毎回のリリースに zip で付ける

- **Status**: Accepted (2026-11-04)
- **Amends**: [ADR-0009](0009-bundle-skill-with-mcp.ja.md)（スキルの置き場所と試験）、
  [ADR-0011](0011-consolidate-skill-into-multi-actor-narration.ja.md)（パッケージの形）

## 背景

ADR-0011 で、スキルを `make package-skill` が作る `multi-actor-narration.skill`
として、別のリリースアセットにした。しかしリリースの手順には、それを作ること・
付けることを必須にする仕組みが無かった。実際に付いたのは v0.4.0 と v0.4.1 の
2 回だけで、v0.4.2〜v0.6.4 の 17 回にはバイナリしか無い（nlink-jp/voice-studio-mcp#3）。
リリースからスキルを入れた利用者は v0.4.1 のスキルを使っており、そのスキルは
v0.5.0 で必須の `work_dir` に置き換わった `workspace_root` を今も教えている。
mcp-tactics は v0.13.0 でこのサーバーを載せなくなったので、利用者がスキルの
存在を知る場所は README とリリースだけになった。

その後、組織の ADR-027（Decision 2）が、ツールに同梱するスキルの形を決めた。
スキルはリポジトリ直下に置く。組織のスキル検証を `make test` に入れる。
サーバーとスキルを両方向から照合する試験を持つ。別のリリースアセットとして
配る。既存のスキルに移動は求めていないが、パッケージを作り直すついでに、
このリポジトリも移すことにした。

## 決定

1. **スキルを `skills/multi-actor-narration/` から、リポジトリ直下の
   `multi-actor-narration/` へ移す。** ここなら、写しとして置いた
   `tests/validate-skill.sh`（組織 ADR-006）が見つけられる。`make test` は
   `go test ./...` の後に検証を走らせる。`skills/build.sh` は消す。
2. **パッケージは `dist/multi-actor-narration-<版>.zip`。** zip の根は
   スキルのフォルダそのもので、アプリのスキル登録が受け付け、skills-series の
   各リポジトリが配っている形と同じ。`.skill` という名前はやめる。
3. **`make package` がバイナリの zip と一緒に作り、`make verify-release` は
   それが無いリリースを拒む。** 前提に置いた `verify-skill-zip` が、その版の
   zip が無いとき、スキルの管理下のファイル以外を含むとき、それらと中身が
   違うときに失敗する。リリースには 2 つの zip を上げる。
4. **`make install-skill` は作った zip から入れる。** ソースの木を写さない。
   パッケージの欠陥は、リリースに届く前に開発者の手元のインストールで表に出る。
5. **試験はスキルとサーバーを両方向から照合する**（`internal/tools/skill_test.go`）:
   - `get_usage` 以外の登録ツールは、すべてスキルが名前を出している。
   - スキルが backtick で囲んだ snake_case の識別子と、`key: value` の例のキーは、
     すべてサーバーにある（1 語の名前は普通の語と見分けられないので照合しない）。登録ツール、
     ツールの入力スキーマのプロパティ、`toolerr` のコード、サーバー自身の型の
     json/toml タグのいずれかで、写しではなくサーバーから読む。サーバーの名前
     ではないもの（スキル自身の資料カードの項目、呼び出し側クライアントの
     ツール）は、何であるかを添えて列挙する。
   - 廃止した名前（`workspace_root` とその綴り違い、`~/.voice-studio`、
     `/radio-drama`、旧パス）が無いことを確かめる。
   - 各フォーマットの台本とキャスティングの雛形が、サーバー自身のパーサーを
     通り、台本がキャスティング表で解決できる。

   最後の照合で、そのままでは使えない雛形が 3 つ見つかった。2 つは、
   キャスティング表に無いスタイルを台本が使っていた。1 つは、表で
   コメントアウトされた役を台本が使っていた。

## 結果

- 最新のスキルが付いていないリリースは、出る前に `verify-release` で止まる。
- サーバーに無い名前をスキルが教えると、スキルのどのファイルにあっても
  `go test` が落ちる。
- README の導入の節は、アプリへの zip の登録から始める。gem-agent と lagent が
  スキルを読む場所（`~/.config/gem-agent/skills/`、`~/.config/lagent/skills/`。
  リンクではなく写す）も書く。
- v0.4.0 と v0.4.1 の `.skill` はそのまま残す。過去のリリースに上げ直しはしない。

## 検討した代替案

| 代替案 | 採らない理由 |
|---|---|
| パッケージだけ直して `skills/` に残す | このリポジトリだけが ADR-027 の配置の例外になり、組織の検証も `make test` に入らない |
| リリースのチェックリストで付け忘れを防ぐ | v0.4.2〜v0.6.4 の間もチェックリストはあったが、毎回飛んだ。文章でしか求めていない手順は飛ぶ |
| 今のスキルを過去のリリースに上げ直す | 過去のリリースのスキルは、そのリリースのサーバーと合っているべき |
