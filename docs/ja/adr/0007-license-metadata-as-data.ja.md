# ADR-0007: 音声モデルの利用規約はコードでなくデータとして扱う

- **Status**: Accepted (2026-07-04)

## Context

本サーバーの成果物はラジオドラマ/朗読音声という**配布物**であり、使用した
音声モデルの利用規約(クレジット表記義務、商用可否など)の遵守が公開の
前提になる。ところがエンジン API(/speakers)はモデルの規約情報を返さない。
AIVMX モデルの規約はソフトウェアライセンス(LGPL 等)とは別建てで、モデル
ごとに異なる(AivisHub の各モデルページ、ACML 等)。

## Decision

規約情報は 2 箇所の「人手が確認した記録」として持ち、ツールがそれを運ぶ:

1. **config `[[speaker_metadata]]`**(マシン単位のレジストリ):
   speaker_uuid → ライセンス名 / URL / クレジット文言 / 商用可否 / 備考。
   `list_speakers` はこれを突合し、未登録モデルを `license.status =
   "unverified"` として返す(エージェントがキャスティング時に規約状態を
   考慮できる)。
2. **casting.toml の `credit` / `license_checked`**(作品単位の記録):
   その作品でそのモデルを使ってよいと人間が確認した事実を記録する。
   `master` は使用キャラクターのクレジットから `<name>.credits.txt` を
   自動生成し、`license_checked = false` のキャラクターを
   `unverified_models` として返却して公開前の確認を促す。

規約の解釈・承認判断そのものは自動化しない(人間の責務)。

## Consequences

- 「どのモデルが確認済みか」がリポジトリ外(config)と作品内(casting)に
  明示的に残り、クレジット漏れを構造的に防げる。
- モデル追加のたびに speaker_metadata の手入力が必要(意図的な摩擦。
  規約を読まずに公開する事故の方が高くつく)。
- 規約が変わった場合の追従は人手(notes に確認日を書く運用を推奨)。

## Alternatives considered

- **AivisHub API 等からの自動取得**: 規約は自然文であり自動解釈は危険。
  また外部アクセスはローカル完結の方針に反する。不採用。
- **規約情報を持たない**: クレジット生成ができず、unverified の警告も
  出せない。配布物を作るツールとして不十分。不採用。
