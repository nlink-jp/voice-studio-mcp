# 資料の取り込みと要点抽出（入力タイプ別）

「資料 → 話す台本」の変換は**解説系4フォーマット**（talk-podcast /
panel-discussion / news-briefing / lesson-narration）の核。まず入力を読み、
**要点カード**（後述）へ落とし、各フォーマットの番組構成に並べ替える。

> **audio-drama（朗読劇）はこの取り込みを使わない**。小説・脚本の原稿を要点
> 抽出せず、物語解析（シーン分割・話者帰属・地の文チャンク化）にかける。
> [../audio-drama/FORMAT.md](../audio-drama/FORMAT.md) を参照。

## 入力タイプ別の読み取り

### PDF / Word 文書
- PDF は `pdf` スキル、Word は `docx` スキルで本文・見出し・表を抽出。
- 見出し階層をそのまま構成の骨格に使える。図表は「本文で何を示すためのものか」
  を1文で言語化して口頭説明に変換（音声では図が見えないため）。
- 長文はセクション単位で要点カード化。全文朗読はしない。

### テーマ / トピック指定（資料なし）
- 資料が無い場合、**確認した事実だけで構成**する。曖昧な最新情報や数値は
  `WebSearch` で裏取りしてから使う（ハルシネーション防止）。
- テーマの「なぜ今」「何が論点か」「聞き手の疑問」を洗い出して構成の柱にする。
- 出典が必要な主張には出典を添える。断定を避け、諸説あるものは併記。

### スライド / データ（pptx / xlsx）
- pptx は `pptx` スキルでスライドテキストとノートを抽出。1 スライド =
  1 トピック単位に対応させやすい。
- xlsx は `xlsx` スキルで読む。数表は**傾向を言葉にする**（「A は前年比 +12%、
  B は横ばい」）。生の数字の羅列を読み上げない。代表値・最大最小・変化だけ拾う。

### チャットセッションそのもの
- 直近の会話や指定セッションを対象化する。長い議論の要約音声、意思決定ログの
  ナレーション化などに使う。`mcp__session_info__list_sessions` /
  `read_transcript` でトランスクリプトを取得できる。
- 会話の「結論」「根拠」「未解決事項」を抽出して構成する。発言者の生ログを
  そのまま読むのではなく、聞いて分かる筋に再構成する。

## 要点カード（中間表現）

抽出した内容は、フォーマットに依存しない要点カードにいったん落とす:

```
- topic: <小見出し>
  key_point: <一番言いたいこと 1 文>
  support: [<根拠・数値・具体例>, ...]
  listener_question: <聞き手が抱く自然な疑問>
  term: [<誤読しそうな固有名詞・専門用語>, ...]  # 発音辞書の元ネタ
```

`listener_question` は対談・教材で「聞き役の問い」に、パネルで「論点」に、
ブリーフィングで「見出し」に変換される。`term` は
[PIPELINE.md](./PIPELINE.md) P3 の発音辞書にそのまま渡す。

## 事実性チェック（必須）

音声は後から訂正しづらい。台本確定前に:
- 資料に無い数字・固有名詞を勝手に足していないか
- テーマ型で最新情報を扱うなら `WebSearch` で裏取りしたか
- 表・グラフの読み替えに誤りがないか
をレビューする。高リスク案件（社外配信・数値主張が多い）は
サブエージェント（Task ツール）で台本を突き合わせ検証すると安全。
